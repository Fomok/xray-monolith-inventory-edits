## Native API contract for Mod/UI

- `actor:sqa_storage_transfer(item, destination)` dispatches direct SELL/BUY without an actor-pocket staging step. `destination` can be the actor, a portable container, or a stash. The item can be a leaf or a loaded portable container. The source can be actor, portable container, stash, or dead stalker. Source membership, live IDs, root custody, source stash `can_take`, destination lifetime, and ancestry cycles are checked before dispatch. Portable-container roots must lead through verified parent links to the actor or a takeable stash; a source may also lead to a dead stalker. The UI must still preflight the exact target cell, size, capacity, access/range and item category, then recheck its own layout record after the transfer settles.
- `actor:sqa_equip_from_container(item, source, slot, return_to_source)` accepts a loaded portable container from a stash or portable container as well as an ordinary item. It reserves the target native slot and can return the displaced item directly to the source. If the source is inside the displaced container, the cycle is refused. UI preflight must check the displaced item's fit in its exact source before calling.
- `actor:sqa_rig_transfer_count()`, `sqa_rig_transfer_pending(id)` and `sqa_rig_transfer_rig_pending(id)` remain the async ownership barriers. Do not serialize a target placement as complete until parent/ownership arrival is observed.
- A `true` transfer result means the request was enqueued or already pending, not that ownership changed synchronously. Observe `sqa_rig_transfer_pending(item:id())` becoming false and re-read the live item's `parent()`; commit the saved layout only when the exact destination owns it. On refusal or failed arrival, keep/recover the source layout. The existing native API does not offer an all-or-nothing multi-item batch transaction, so migration of an equipped bag's old actor-grid items must be staged item by item before the bag itself moves.
- `actor:sqa_nested_storage_version()` returns `1` only on the new engine. Gate the new backpack and nested paths on this additive capability. The existing `sqa_box_layout_version()==1` remains unchanged.
- `container:iterate_container(callback, context)` still visits direct children only. The UI can recurse into a child that `is_container()` returns true for, checking actual `parent()` at each level. Native actor possession, quest enumeration and mass now walk nested carried children.
- Native possession of a nested item does not by itself permit quick-use. `CInventory::Eat` requires an installed `_G.AMP__before_eat(item)` callback to return true for an item nested beyond one container. The mod must decide manual access and quick-use from its actual open-window state and item ancestry; absence of the hook refuses nested consumption.
- Normal `II_BPACK` is still a `CBackpack`, with its slot, upgrades and section IDs unchanged. It now inherits `CInventoryContainer` on the client, so `is_container()` and direct child iteration work on that same live object. Its factory server type is `CSE_ALifeItemContainer` under the unchanged `CLSID_EQUIPMENT_BACKPACK`; this enables the existing recursive child restoration on root drop and actor/stash switching. `CSE_ALifeItemContainer::STATE_Read/Write` and `UPDATE_Read/Write` delegate directly to `CSE_ALifeItem` with no added packet fields, so old backpack item records keep their format. The server accepts `set_box_layout(backpack, ...)` using the existing version-1 box layout record. The mod must migrate items assigned to the *equipped* backpack's actor grid by direct `sqa_storage_transfer(item, backpack)` while keeping each item's saved grid coordinates, then show those children when the bag is unequipped. Do not infer child ownership from grid position alone. Before any unequip/drop/stash move, wait for the migration's pending transfers to settle; reject or defer the move if any child is still actor-owned. On an old save, make migration idempotent: skip children already parented to that backpack and leave items with ambiguous or other storage membership untouched for explicit handling.
- The engine does not choose a pocket or grid position. Keep the public mod's existing saved placement metadata; do not import SQA3 ledger or save format. Exact destination is the UI's responsibility.
