Squared Away Personal DLSS Frame Generation Test 4 — DX11 AVX
EXPERIMENTAL personal build. Test 3 generated frames in game; Test 4 integration still needs gameplay validation.

Use a separate test copy/profile. Install the COMPLETE bin/ + db/ package over
the same Bodycam+DLSS baseline used for bridge test 1. Keep the public grass/motion
shader patch and Bodycam GAMMA Patch 1.1.0. Do not mix frozen weapon-follow/pivot builds.
Keep bin/streamline/ beside AnomalyDX11AVX.exe, including all six supplied DLLs.

DEFAULT OFF. NVIDIA RTX 40/50, supported driver/Windows and Hardware-accelerated GPU
Scheduling are checked by the SDK. This test targets RTX 5080. SDR windowed/borderless.
1. Set SQA_DLSS_FG=1 in the environment of the test game/MO2 process, then restart:
     $env:SQA_DLSS_FG = '1'
   This loads the FG-capable bridge. SQA_DX12_BRIDGE=1 alone remains bridge-only.
2. Enable DLAA or DLSS Quality (FSR3 upscaling can also supply temporal inputs).
   MSAA must be off; keep the matching SSS motion-vector shaders.
3. Start with VSync off. In the game console enter: r_dlss_fg 1
   Turn generation off with: r_dlss_fg 0
   The setting can persist in the test profile; omit SQA_DLSS_FG to prevent runtime loading.
4. Look for capability/runtime-ready messages, "Interpolation enabled (2x)", and
   [FG DIAG] PostPresent ... presented=2 / status=0x0. SDK support or the enable
   message alone is NOT proof that extra frames were generated.
5. Compare the same scene/save with r_dlss_fg 0 and 1. Record smoothness, latency,
   UI/text edges, artifacts and frame times. The engine's simulation-FPS counter
   does not prove displayed FPS. r__framelimit remains a rendered-FPS cap.

Generation suspends in menus/loading/pause/unfocused windows, scopes/PiP, night vision,
thermal and item/camera UI; those views render normally without generated frames.
Actor-attached wearable UI is now protected by a clean-scene capture and UI mask,
allowing generation while its widgets/glass are present.
Returning to eligible gameplay resets temporal history. The UI mask conservatively
protects changed pixels; translucent edges and world-space overlays remain a test risk.
The bridge orders GPU writes after FG input retirement; this version prioritizes
correctness while allowing CPU preparation to overlap the prior GPU frame. Frame-generation quality is not certified.

Resize uses a synchronized suspend path. If a device rebuild shuts Streamline down,
restart the game to use FG again; repeated Streamline initialization is deliberately
blocked. Missing/unsupported runtime falls back to native DX11. A synchronization
failure stops with instructions instead of continuing with unsafe GPU resources.

Optional bin/bridge_probe.exe tests ordinary bridge transport.
bin/bridge_probe.exe --streamline checks SDK capability/Reflex/proxy presentation
in a hidden standalone window with generation OFF, not actual interpolation.

Rollback: r_dlss_fg 0; quit; unset SQA_DLSS_FG and SQA_DX12_BRIDGE, then restart.
Restore the previous complete engine package to undo the build.
No public release/website or installed files were changed by Codex.

TEST 4: OPTISCALER DLSS-NR + PERSONAL FG
The supplied Full Pack uses the wilsjo2 DLSS-NR fork, not official OptiScaler.
Its existing FrameGen.External=true startup mode keeps NR/SR enabled while leaving
Streamline/Reflex/FG to the game. Keep OptiScaler's own FG disabled. Use
Upscalers.Dx11Upscaler=dlss_12 and DlssNr.Enabled=true for Neural Rendering.
Also set Menu.OverlayMenu=false to use the legacy menu path. External=true alone
still crashed the combined probe with the default overlay path. Legacy menu mode
passed with the exact supplied DLL; no fork replacement is required.
Restart after changing External or OverlayMenu; live changes cannot undo hooks.
A separately prepared OptiScaler settings ZIP is supplied for the known Full Pack.
Back up your installed OptiScaler.ini, then copy that ZIP's bin/OptiScaler.ini into
Anomaly/bin. It is a bin configuration, NOT an MO2 mod. Restore your backup to undo.
For your customized INI, tools/prepare-optiscaler-personal.ps1 takes -SourceIni and
-OutputDirectory, preserves other settings and writes a separate prepared file.
It sets those four keys and refuses to overwrite its source or an existing output.
Copy manually after review. Other overlay-blocking or factory-wrapping changes
are not required by the successful isolated test.
Do not replace the DLSS-NR fork with official OptiScaler just to match a newer version:
the official source checked does not provide this fork's Neural Rendering path.

The engine supplies a real unity-exposure texture for SDR, preventing OptiScaler's
missing-exposure fallback recreation. Timeout diagnostics now distinguish an engine
retirement timeout from an actual DX12 device-removal reason. Neither change alone
proves that the reported hot-switch crash is fixed.

Wearable screens/glass retain native rendering and occlusion. FG now captures the
scene before their native draw, applies identical final postprocess to the clean
scene and displayed frame, and protects overlay pixels with the conservative mask.
No Wearable Devices script replacement or MO2 patch is required for this approach.
Translucent glass edges and moving wrist screens still require visual validation;
the mask copies affected current-frame pixels instead of interpolating their UI.
Item/camera UI and scope/vision exclusions remain.

Validation sequence: fresh launch with prepared External=true config; fixed DLSS
w/DX12 backend; test personal FG off/on, then NR off/on, then Promin/Vektor equipped.
Require sustained presented=2/status=0, no exposure-recreation warning and no timeout.
Compare UI readability, hand/glass occlusion, movement edges and frame times. Only
after stable fixed-backend operation, test backend transitions in a disposable
session, initially with r_dlss_fg 0. Save complete engine and OptiScaler logs.
Probe --streamline --ngx uses synthetic DLAA inputs and recreates NGX across resizes;
it is an interoperability check with FG OFF, not proof of gameplay/NR image quality.
Probe --streamline --ngx --generate additionally submits synthetic FG inputs and requires at least 900 two-frame presentations across 960 calls. bridge-probe-result.txt records counts even when an injected overlay redirects stdout. It still does not test the game's wearable render path or displayed image quality.

and OverlayMenu=false each completed 960 presentations, seven resizes, eight NGX
feature creations/readbacks, and 953 generated presentations (seven resize warmups).
