# Rig condition and retained pouch recovery

Source policy verified in full release development source C:/GAMMA/sqa-previews/release-2.1.0-hotfix1-full/source/gamedata/scripts/zzz_armor_mag_pouches.script:4275-4394,5278-5319,5888-5934,6067-6108. Mount thresholds control available grants; an attached pouch remains fitted when its slot becomes inactive and returns on repair. Rig tears exclude separately fitted pouch pockets. Native damage must not be refused merely because contents no longer fit. No installed files were read for this audit.

Shared Model now distinguishes retained attachment validity from current storage availability. storage_active and cell_region expose disabled storage as unavailable; it contributes zero granted capacity but retains pouch identity and intrinsic mass. Ordinary Mount/Spawn admission into a disabled slot fails. A retained inactive pouch must be empty. Ordinary SetState still refuses a change requiring recovery, so native damage must use the explicit reconciliation API, not silently discard its error.

recover_rig_condition(rig, condition, actor, revision, session) is a forced native-controller transaction for directly actor-owned rigs only. It changes condition and moves direct contents of newly inactive pouches, including intact nested subtrees, into actor recovery. The pouch itself stays attached. If loss of granted capacity changes a soft rig's fullness and its exterior no longer fits, the whole rig is retained in recovery. One final validation and one revision publish; invalid condition/ownership/stale request leaves the model unchanged. IDs, high-water, mass and unrelated manual placements stay intact. Repair restores grant availability but does not silently repack recovery items. Layout rendering never mutates ownership.

70 debug/release behavioral tests plus independent-process reload pass in C:/GAMMA/sqa-previews/inventory-next-20261027/milestone7-condition-build. Cases include loaded nested pouch recovery, empty retained pouch, exact repair threshold, saved inactive state, stale/foreign/invalid rejection, disabled new attachment, and loss-of-capacity exterior collision. This supersedes the earlier test that expected all condition decreases below mount minimum to fail.
