# Native transfer protocol foundation

TransferSession validates Move/Equip/Mount through AccessGate and the same Model, then reserves an immutable candidate. Source, destination and all moved descendants must have live generation/epoch handles. No model change occurs at prepare or dispatch. Native event delivery alone is not success: acknowledgment must carry the unique transaction token and observed expected parent with unchanged core/access/handles. Only then is the candidate published once. Explicit native rejection with original parent preserves state. Unknown parent, stale generation, or concurrent model edit after dispatch blocks writes/save until an explicit validated Model rebuild changes the epoch. Cancel cannot pretend to undo a dispatched native event. Duplicate/wrong-token acknowledgments never commit.

59 local core tests pass per build including success, rejected native ownership, uncertain parent, missing rebuild, reused live ID and concurrent state change. This protocol is compiled in the shared library, NOT yet wired to real server ownership events; it does not claim native transactions or rollback of arbitrary side effects.

Native source boundaries inspected: xrServer_process_event_ownership.cpp calls game->OnTouch (ALife attach) before server parent update/broadcast; xrServer_process_event_reject.cpp detaches before broadcasting; xrServer_perform_transfer.cpp separately rewrites both parent lists. CInventory::Take and DropItem mutate native slot/ruck lists and callbacks. CInventoryItem::OnEvent does not currently implement inventory-child ownership. CInventoryBox does, but is not an inventory item. Native nested containers therefore require their own gated event handling, server preflight before detach, client completion acknowledgment, and mass invalidation through actor ancestors. A failed target after ordinary reject/take must not be reported as atomic success.
